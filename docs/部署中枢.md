# 部署中枢

中枢是一个跑在你自己电脑上的服务：加密存储、多设备同步、网页管理台、APK 下载页和开发工具接口。如果你只是拿到 APK 想用手机记事、设提醒、收截图或连接自己的聊天模型，可以直接看[手机快速开始](../README.md#快速开始)。需要共享清单、让电脑接续项目或接入家居和邮箱时，再按下文部署。

推荐的运行方式是 Docker Compose。容器根文件系统只读，去掉全部 Linux 权限，数据放在外部命名卷，资料库密钥由宿主机上的一个文件提供，二者都不进镜像。镜像里另带 Node.js 和固定版本的 `flyai` 命令行（飞猪查询用），不需要另外安装。macOS 登录项形式的原生服务只作为[附录](#附录原生服务)保留。

## 前置条件

- 一台常开的电脑（文中以 Mac 为例），装有 Docker 与 Compose。
- Python 3.11 或更新版本和 Git，只用于第一次初始化资料库和生成密钥文件。
- 手机和中枢在同一局域网，或都装了 Tailscale。

## S7 中枢联想的启用条件

本阶段不增加环境变量或部署依赖。升级后通过 `/api/preview/health` 的 `thought_candidates_v1` 协商；需模型配置包含本人空间与 `proactive` 角色、主动总开关开启，以及手机单独上传的有效念头授权清单。旧设置中明确关闭的 `model_proactive:false` 仍然生效；未设置此项时，新清单本身是独立的模型主动授权。没有清单不会启动新联想，旧手机仍可同步。手机通过 `last_success_at` 判断中枢最近是否成功联想，中枢离线或不支持时由手机自行兜底。

早晚按资料库时区8/20点调度，事件合并节流30分钟；每日本功能至多2次定时+2次事件，另受模型总调用额度及60,000 token保守预占约束。单次45秒超时不重试、不退预占。候选仅供鉴权拉取，不推送到设备。城市共享需在清单中单独 `city_sharing:true`；反馈学习可单独关闭。授权与候选保存在加密私有侧表，不进入同步或备份，恢复后需要手机重新授权；首次授权登记的交付所有者不因离线自动换机。

灾害预警暂未集成可信官方源，接口明确 `available:false`；部署者不能用新闻源代替预警。汇率的日期化历史基准走既有 Frankfurter/ECB 参考数据服务，无额外密钥。

## 第一次部署

### 1. 初始化资料库与证书

```sh
git clone https://github.com/Annuts/Mellow-Public.git Mellow && cd Mellow
python3 -m venv services/center/.venv
services/center/.venv/bin/python -m pip install -e services/center

MELLOW_DATA="$HOME/Library/Application Support/MellowCenter"
services/center/.venv/bin/mellow-center --data-dir "$MELLOW_DATA" init \
  --hostname mellow-mini.local --hostname 100.x.y.z
```

`init` 要求一个至少 12 个字符的资料库口令，并生成自签 TLS 证书。`--hostname` 可以重复，把你会用到的主机名和 IP（包括 Tailscale 地址）都加上，手机访问的地址必须在这个列表里。记下输出的两个指纹。`init` 不会覆盖已有的库。

### 2. 生成密钥文件

容器用一个 32 字节的密钥文件解锁资料库，它由口令和库里的盐值算出，权限必须是 0600，放在仓库之外：

```sh
MELLOW_KEY="$HOME/Library/Application Support/MellowDocker/vault.key"
mkdir -p "$(dirname "$MELLOW_KEY")"
services/center/.venv/bin/python - "$MELLOW_DATA" "$MELLOW_KEY" <<'PY'
import getpass, os, sqlite3, sys
from pathlib import Path
from mellow_center.vault import derive
data, out = Path(sys.argv[1]), Path(sys.argv[2])
salt = sqlite3.connect(data / 'vault.sqlite3').execute('SELECT salt FROM vault WHERE id=1').fetchone()[0]
key = derive(getpass.getpass('资料库口令: '), salt)
with os.fdopen(os.open(out, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600), 'wb') as f:
    f.write(key)
PY
```

### 3. 创建数据卷

```sh
docker volume create mellow_center_data
docker run --rm -v mellow_center_data:/data -v "$MELLOW_DATA":/src:ro alpine \
  sh -c "cp -a /src/. /data/ && chown -R $(id -u):$(id -g) /data"
```

### 4. 写 production.env

在仓库外建一个环境文件，例如和密钥文件放在同一目录：

```sh
MELLOW_KEY_FILE='/Users/你/Library/Application Support/MellowDocker/vault.key'
MELLOW_UID=501                  # id -u
MELLOW_GID=20                   # id -g
MELLOW_BIND=0.0.0.0             # 默认只监听本机。手机要连就用 0.0.0.0 或 Tailscale 地址
MELLOW_DOWNLOADS='/Users/你/Library/Application Support/MellowDocker/downloads'
# FLYAI_API_KEY=...             # 可选，飞猪查询的密钥，见下表
```

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `MELLOW_KEY_FILE` | 必填 | 密钥文件路径，以 Compose secret 只读挂载 |
| `MELLOW_UID`、`MELLOW_GID` | 1000 | 容器用户，要和数据卷的属主一致 |
| `MELLOW_BIND`、`MELLOW_PORT` | 127.0.0.1、8765 | 宿主机监听地址和端口 |
| `MELLOW_VOLUME` | `mellow_center_data` | 外部数据卷名 |
| `MELLOW_DOWNLOADS` | `./downloads` | 宿主机上的 APK 下载目录，容器内只读挂载到 `/var/lib/mellow-downloads` |
| `MELLOW_DOWNLOADS_DIR` | `/var/lib/mellow-downloads` | 容器内下载目录的路径，是服务读取的位置。`compose.yaml` 不透传它，一般不用改 |
| `MELLOW_DOWNLOADS_PUBLIC_LAN` | 1 | 局域网和 Tailscale 内是否免登录下载，设 0 则必须带设备令牌或管理员 Cookie |
| `FLYAI_API_KEY` | 空 | 飞猪查询的密钥，由 `compose.yaml` 传进容器，改后重启。不设时走飞猪体验模式 |
| `MELLOW_EMBED_MODEL_DIR` | 未设 | 指定语义模型目录，设了就以它为准，不再找数据卷和镜像内置的模型。`compose.yaml` 不透传它，要用就自己加到 `environment` |
| `MELLOW_PYTHON_IMAGE` | `python:3.11-slim-bookworm` | 基础镜像，国内网络可换镜像源 |
| `MELLOW_MODEL_MIRROR` | `hf-mirror.com` | 构建时下载语义模型的优先源。设成 `hf-mirror.com` 先试镜像，其他值（含空）先试 huggingface.co |

部署前下载目录要先建好：`mkdir -p "…/downloads"`。

### 5. 启动

```sh
docker compose --env-file production.env up -d --build --wait
docker compose --env-file production.env ps
docker compose --env-file production.env logs --tail 60 center
```

`--wait` 等到健康检查通过才返回。健康检查用容器内的证书请求 `/api/preview/health`，状态为 `ready` 才算健康。首次构建会下载固定版本的语义模型，见[语义模型](#语义模型)。

确认容器正常运行后，把初始化用的那份宿主机数据目录（`$MELLOW_DATA`）挪到安全的地方或删除。两份库各自演变会造成分叉。挪走之前，先把证书拷出来，后面的健康检查和浏览器信任还要用：

```sh
docker compose --env-file production.env cp center:/var/lib/mellow/tls.crt ./mellow-tls.crt
```

### 6. 配对手机

容器里没有宿主机的钥匙串，所以配对用 `exec`，并输入资料库口令：

```sh
docker compose --env-file production.env exec -it center \
  python -m mellow_center --data-dir /var/lib/mellow pair --name 我的手机 \
--space personal --admin \
  --lan https://mellow-mini.local:8765 --tail https://100.x.y.z:8765
```

命令输出一段 JSON 邀请，10 分钟内有效，只能用一次，里面带着证书指纹。在手机上打开「我的 → 连接 → 家里的小满主机 → 连接小满主机」粘贴。`--lan` 是主地址，`--tail` 是备用地址，手机先试主地址再试备用。`.local` 解析不了时直接用 Mac 的 IP。去掉 `--admin` 得到非管理员设备。邀请只在你自己的设备间传递，别贴进聊天或 Git。

### 7. 打开网页管理台

浏览器访问 `https://mellow-mini.local:8765/console`，第一次需要在这台设备上信任 `tls.crt` 并核对指纹。登录有两种方式：

- **管理员邀请**：`pair ... --admin` 生成，登录后 8 小时有效。
- **接入口令**：`rotate-access-token` 打印以 `xm_` 开头的口令，登录后这台浏览器保持一年。轮换口令不会让已登录的设备失效。

```sh
docker compose --env-file production.env exec center \
  python -m mellow_center --data-dir /var/lib/mellow rotate-access-token
```

## 手机下载页

中枢自带 APK 下载页，地址 `https://<主机>:8765/downloads/`。页面列出最近三个构建：版本、构建号、大小、构建日期和 SHA-256，以及指向最新版的固定链接 `/downloads/android/latest.apk`。

局域网和 Tailscale 地址段内的访问不需要登录（`MELLOW_DOWNLOADS_PUBLIC_LAN=1`）。其他来源，或把这个变量设为 0 时，需要设备的 Bearer 令牌或管理员网页 Cookie。中枢不信任 `X-Forwarded-For`。

浏览器会提示自签证书不受信任，核对指纹后继续。下载后可以用 `shasum -a 256` 对照页面上的 SHA-256。更新前先在应用里导出加密备份，直接覆盖安装，不要卸载旧版。

## 语义模型

中枢的检索是词法加语义的混合。语义用 BAAI/bge-small-zh-v1.5 的 ONNX 版本，在 CPU 上运行，所有向量加密存在资料库里。

模型在镜像构建的第一阶段下载，每个文件按固定的 SHA-256 校验，每个文件最多重试三轮。`compose.yaml` 把构建参数 `MELLOW_MODEL_MIRROR` 默认设为 `hf-mirror.com`，所以用 Compose 构建时先试国内镜像 hf-mirror.com，失败再试 huggingface.co；不经 Compose 直接构建，或把变量设成空，则顺序反过来。运行时不联网，镜像里的目录由 `MELLOW_BUILTIN_MODEL_DIR` 指向。没有模型文件时语义检索自动关闭，词法检索照常工作。

- 健康接口的 `semantic` 字段为 `ready`、`indexing` 或 `disabled`。`indexing` 表示模型已加载，向量索引还在追赶，等它变成 `ready` 即可。管理员用 `status` 命令能看到索引条数、失败数和模型编号：

  ```sh
  docker compose --env-file production.env exec -it center \
    python -m mellow_center --data-dir /var/lib/mellow status
  ```
- 数据目录下的 `models/bge-small-zh-v1.5/` 优先于镜像内置模型。手动更新模型：`exec center python -m mellow_center --data-dir /var/lib/mellow models fetch`，再重启容器。
- 重建向量索引：`exec -it center python -m mellow_center --data-dir /var/lib/mellow index rebuild`。向量只是派生数据，删掉原文后会被清理。

## 局域网发现

容器模式默认关闭了 mDNS 广播，直接按第 6 步粘贴配对邀请连接即可。如果使用[附录：原生服务](#附录原生服务)，局域网发现是内置开启的。

## Tailscale 与异地使用

中枢不提供公网中继。异地使用请在电脑和手机上都装 Tailscale，把 Tailscale 地址作为 `--tail` 备用地址配对，并在 `init --hostname` 里加上它。`MELLOW_BIND` 要包含 Tailscale 网卡，即 `0.0.0.0` 或具体的 Tailscale 地址。

mDNS 只在同一局域网内有效，需要放行 UDP 5353 和 TCP 8765。访客 Wi-Fi 的客户端隔离会挡住发现，这时直接粘贴邀请。

## 证书

自签证书有效期 365 天，手机同时核对整张证书的指纹和公钥（SPKI）指纹。

- **自动续期**：每次 `serve` 启动时，证书不足 60 天到期就用同一把私钥重签。公钥不变，手机无需重新配对。
- **手动续期**：保留私钥和原有的主机名，续期后重启容器让新证书生效。

  ```sh
  docker compose --env-file production.env exec center python -m mellow_center --data-dir /var/lib/mellow tls renew
  docker compose --env-file production.env restart center
  ```

- **到期提醒**：健康接口返回 `tls_expires_at`，不足 30 天时 `tls_expiring` 为 true，日志里会有 `TLS_EXPIRING`。

中枢只在启动时检查证书。容器长期不重启的话，请在到期前 60 天内重启一次，或手动续期。

## 备份与恢复

备份用独立的口令加密，请和资料库口令分开保存。在容器里生成，再拷出来：

```sh
docker compose --env-file production.env exec -it center \
  python -m mellow_center --data-dir /var/lib/mellow backup --output /var/lib/mellow/backups/manual.enc
docker compose --env-file production.env cp center:/var/lib/mellow/backups/manual.enc ./manual.enc
```

口令至少 12 个字符，要输入两次。输出目录不存在时会自动创建（权限 0700）。同名文件已存在时命令会拒绝覆盖，换一个文件名，或先删掉旧文件。

每日自动备份可以用 `backup-policy --directory /var/lib/mellow/backups --keep 7 --hour 3 --timezone Asia/Shanghai` 配置，也可以在网页管理台的「备份」页设置。想停用，运行 `backup-policy --disable`，已有的备份文件会保留。备份文件在数据卷里，记得另存一份到别处。

备份**包含**业务记录、删除记录、偏好设置、家庭空间、上下文、人生对象、档案笔记和信件，**不含**模型密钥、设备凭据、TLS 私钥、连接器配置和外部生活账户凭据。仅保存在手机里的内容不在中枢备份里，手机有自己的加密备份。向量索引和下载目录也不在备份里，前者可以重建，后者可以重新发布。恢复出来的托付一律是已撤销状态，需要重新设置。

命令行恢复 `recover-empty` 必须在全新初始化的空库上、在配对设备之前做，库里已有记录、删除记录或设备时会拒绝：

```sh
docker compose --env-file production.env exec -it center \
  python -m mellow_center --data-dir /var/lib/mellow recover-empty --input /var/lib/mellow/backups/manual.enc
```

恢复后重新配对设备、重新填写模型密钥和外部账户凭据，主动建议默认保持关闭。已有数据的库不受这个限制，请用网页管理台或管理员手机的「预览并恢复备份」（对应接口 `/restore/preview` 和 `/restore/commit`），它先列出新增、冲突和删除的数量。冲突时保留当前记录，备份里的删除记录会生效。

## 升级

升级前先备份，不要对已有的库重新 `init`。在仓库目录拉取最新代码后重新构建启动即可：

```sh
git pull --ff-only
docker compose --env-file production.env up -d --build --wait
```

## 外部生活账户的网络

同机的 Home Assistant 容器，在网页管理台「外部生活账户」里填 `http://host.docker.internal:8123`（Docker Desktop）或自己的局域网地址。令牌只写入中枢加密凭据。IMAP 开启后由独立循环最多每 15 分钟读一次信头，白名单为空时不联网。

## 排查

先看健康接口，它不需要登录。`--cacert` 用的是第 5 步拷出来的证书，没拷的话现在可以用 `docker compose cp` 补一份：

```sh
curl --cacert ./mellow-tls.crt https://localhost:8765/api/preview/health
```

`status` 为 `ready` 表示正常，`degraded` 表示某个后台步骤连续失败。`worker` 字段列出各步骤（语义索引、任务、发现、规则、备份、清理、热点）最近成功时间和连续失败次数。后台步骤互相隔离，失败后按指数退避重试，不拖垮其他步骤。

| 现象 | 处理 |
| --- | --- |
| 手机连不上 | 确认地址和端口，`MELLOW_BIND` 不是 127.0.0.1，防火墙放行；先在手机浏览器打开 `/api/preview/health`；换成 IP 地址 |
| 提示证书不符 | 对照 `status` 输出的指纹。证书如果被重新生成，需要重新配对 |
| 网页管理台打不开 | 在这台设备上信任 `tls.crt`，地址必须在证书的主机名列表里 |
| 容器不健康 | `logs` 里找 `VAULT_UNLOCK_FAILED`：多半是密钥文件不对或权限不是 0600 |
| 容器反复重启，权限错误 | `MELLOW_UID`、`MELLOW_GID` 要和数据卷属主一致，重新执行建卷时的 `chown` |
| `A Mellow worker is already running` | 同一个库只能有一个服务进程，先停掉另一个 |
| 无法解锁资料库 | 核对口令和数据目录。中枢不会因此重置数据 |
| 下载页显示「暂时没有可下载的安装包」 | 下载目录为空，或 `MELLOW_DOWNLOADS` 路径没有挂对 |
| 下载页返回 401 | 客户端不在局域网或 Tailscale 地址段，或 `MELLOW_DOWNLOADS_PUBLIC_LAN=0`，请带设备令牌或登录管理台 |
| `semantic` 是 `disabled` | 镜像构建时没下载到模型。重新构建，或用 `models fetch` 手动获取并重启 |
| `semantic` 长时间是 `indexing` | 向量还在后台补算，库大时需要一阵。用 `status` 看索引条数，持续不动再查日志 |
| 建议收不到 | 先看手机「我的 → 提醒与打扰」，再看[使用指南](使用指南.md#准时提醒与精确闹钟权限) |

日志里只有错误码、异常类型和数字，没有用户内容。

## 数据放在哪

容器内数据目录 `/var/lib/mellow`（即数据卷）：

- `vault.sqlite3`：资料库，逐记录加密，含向量索引。
- `tls.crt`、`tls.key`：TLS 证书和私钥。
- `owner-access.sha256`：接入口令的哈希。
- `backups/`：自动备份。
- `cache/public-data/`：公共数据缓存，非用户内容。
- `whatshot-public.json`：公开热榜缓存。
- `models/`：手动获取的语义模型，可选。

这些都不进 Git。模型密钥保存在加密库内，不写明文文件。

## 附录：原生服务

不用 Docker 时，可以把中枢注册成 macOS 登录项，密钥放在登录钥匙串。数据格式与 Docker 相同，可以互相迁移。原生方式没有容器隔离，局域网发现是内置的，不需要额外脚本。

```sh
services/center/.venv/bin/mellow-center --data-dir "$MELLOW_DATA" service-install --host 0.0.0.0 --port 8765
services/center/.venv/bin/mellow-center --data-dir "$MELLOW_DATA" status
```

日志在数据目录的 `service.log`。如果旧服务占着 8765，先对旧数据目录执行 `service-uninstall`，它只停服务，不删数据。只想临时试用，把 `service-install` 换成 `serve`，每次启动输入口令。

原生运行时 `serve` 的密钥来源有三种：交互输入口令、`--keychain`（读登录钥匙串）和 `--vault-key-file <文件>`（读 32 字节密钥文件，Compose 容器就是这样启动的）。

手机里「语音 → 小满主机识别」需要中枢上有本地语音模型。官方镜像不含语音扩展，要用的话在原生环境安装并下载模型，再重启中枢：

```sh
services/center/.venv/bin/python -m pip install -e 'services/center[voice]'
services/center/.venv/bin/mellow-center --data-dir "$MELLOW_DATA" voice-setup --model small   # 也可选 base
```
